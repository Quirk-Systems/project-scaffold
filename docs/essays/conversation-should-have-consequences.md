# Conversation Should Have Consequences

Most conversational systems treat the final answer as the product. That is
occasionally correct and usually expensive.

A substantial conversation creates more than prose: it changes definitions,
retires assumptions, reveals preferences, exposes missing capabilities,
produces decisions, and leaves half-built machinery behind. A summary can
describe that activity while preserving almost none of its leverage. The next
conversation pays the same discovery tax again.

The Quirk Conversation Compiler treats dialogue as a source event and asks a
harder question: **what deserves to survive in a form that can be inspected,
reused, tested, rejected, or enforced?**

## The unit of value is the delta

The transcript is evidence. The delta is the product.

A delta might be a corrected name, a rejected architecture, a new permission
boundary, a prompt that became reliable enough to register, an eval fixture
born from failure, or a clean no-op because the discussion produced nothing
durable. The compiler's first act is subtraction: remove conversational
ceremony, repeated explanations, and assistant language that never acquired
authority.

That subtraction is not compression for its own sake. It protects the system
from three kinds of rot:

1. **Canon inflation** — ideas become “truth” because they were written with
   confidence.
2. **Artifact confetti** — every memorable phrase receives a file, folder, or
   repository before it earns an owner or lifecycle.
3. **Historical erasure** — late polish steamrolls early strangeness, including
   rejected material that contains the actual invention.

## Conversation is allowed to fail cleanly

The no-op is a first-class output. Without it, the compiler is paid in file
count and will manufacture consequences. That is documentation landfill with
better typography.

The system therefore separates `CANON`, `EVIDENCE`, `INFERENCE`, `PROPOSAL`,
`OPEN`, `DEPRECATED`, and `BONEYARD`. These are not decorative labels. They
prevent the output of one model turn from quietly obtaining governance power.

Corrections remain linked to what they supersede. Contradictions remain visible
until evidence or authority resolves them. Rejected material survives only
when it has a named salvageable part and a real reanimation trigger.

## Authority has to enter from outside the compiler

A model cannot certify its own memory of who spoke, declare its paraphrase
adopted, or generate a receipt for work it merely described. Those are all the
same category error: content awarding itself authority.

The host must bind source identity to a content hash, bind CANON to an exact
statement grant, bind routing to a pinned repository tree, bind mutation to a
mode/action/repository/path scope, and bind external outcomes to executor-owned
receipts. The compiler may transform and cite that context, but cannot widen
it. This makes trust a boundary of the system instead of another field the
system fills in optimistically.

## Genius is metadata

“Genius” is useful as a signal and terrible as a filing system. A brilliant
prompt is still a prompt. A brilliant failure is still an eval fixture. A
brilliant dead end belongs in the boneyard with the mechanism that made it
interesting.

Typing the object protects the exceptional part from becoming untouchable. It
can receive an owner, contract, test, version, consumer, and reversal rule.
Admiration graduates into maintenance.

## Eleven compounding extensions

These remain proposals until usage evidence promotes them:

1. **Semantic rerun diff** — prove idempotence by comparing object meaning, not
   generated wording.
2. **Correction radar** — prioritize late user corrections before all other
   extraction.
3. **Canon quarantine** — hold new CANON candidates until authority and
   collision checks pass.
4. **Conversation yield ratio** — compare durable units with artifact count to
   expose transcript taxidermy and repo confetti.
5. **Boneyard pressure gauge** — surface repeated resurrection triggers as a
   likely architecture-boundary failure.
6. **Cross-repo change set** — stage multi-repo consequences as one atomic,
   reviewable proposal with per-repo proofs.
7. **Preference provenance edge** — record who expressed a preference, in what
   context, with what confidence and reversibility.
8. **No-op receipts** — preserve why no artifact was justified so future agents
   do not repeat the same manufacture attempt.
9. **Contradiction heatmap** — rank conflicts by downstream blast radius rather
   than rhetorical intensity.
10. **Capability deposit ledger** — measure which conversations created reusable
    machinery and whether anyone consumed it later.
11. **Disciplined wildcard: Misread Dividend** — detect deliberate or accidental
    interpretations that produced a superior meaning, preserve both readings,
    and require proof before promoting the better mistake.

## The standard

Files existing is not success. A repository can become consistently wrong in
perfect formation.

The standard is stranger and stricter: preserve the valuable difference,
identify whose authority made it real, place it where it can survive, prove it
does what it claims, and leave enough lineage that a future system can disagree
intelligently.

Conversation should have consequences. Only the deserved ones.
